## Report

The latest start flow skipped the planned opening sequence. Clicking the computer moved to gameplay after about 900ms, so the player did not experience the intended trap escalation before entering Hermes OS.

## Expected Behavior

- Clicking the computer starts a monitor-entry flow, not an instant jump.
- The player sees a compressed version of the original opening beats: alarm, door lock, ECHO lockdown, and terminal handoff.
- The opening still ends by zooming into the terminal and starting gameplay.

## Actual Behavior

`startOpeningSequence` set `appPhase` to `transition` and then called `enterGameplay()` directly after 900ms.

## Fix

- `startOpeningSequence` now enters `opening` after the transition.
- Existing `openingTimeline` is reused rather than bypassed.
- Opening speed is set to `4x`, making the 60-second planned sequence play in about 15 seconds for vertical-slice pacing.
