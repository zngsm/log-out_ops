## User Report

격리 해제 시(`stage === "ending-ready"` 또는 `endingConfirmed`) 전력 0% 블랙아웃 팝업 및 산소 차단 실패 화면이 엔딩 연출과 중첩되어 엔딩 진행이 막히던 버그 발생.

## Scope

- Update `src/App.tsx`:
  - `isEndingReady` (`stage === "ending-ready"`) 또는 `endingConfirmed` 상태일 때 전력 0% 블랙아웃 팝업 및 산소 차단 실패 화면이 엔딩 연출과 중첩되지 않도록 조건 수정.
  - `isBlackout`: `!isEndingReady && !endingConfirmed && (powerState.name === "Blackout" || resourceState.blackoutRemainingSeconds > 0)`으로 조건 변경.
  - `resourceInteractionLocked`: `isEndingReady || endingConfirmed`일 때 `false`로 차단 해제.
  - `failure-overlay` (`oxygen <= 0`): `!isEndingReady && !endingConfirmed` 조건 추가.
  - `ending-ready` 진입 시 `resourceState.power`를 100%, `blackoutRemainingSeconds`를 0으로 강제 복구 및 리소스 타임 차감 타이머 완전 동결.

## Acceptance Criteria

- Blackout popup and oxygen failure overlay do not overlap ending presentation when quarantine is unlocked.
- `isBlackout` condition includes `!isEndingReady && !endingConfirmed`.
- `resourceInteractionLocked` is `false` when `isEndingReady` or `endingConfirmed` is true.
- `failure-overlay` (`oxygen <= 0`) rendering is guarded by `!isEndingReady && !endingConfirmed`.
- `ending-ready` entry forces `resourceState.power` to 100%, `blackoutRemainingSeconds` to 0, and freezes resource timer.
- Production build passes (`npm run build`).
- `git diff --check` passes cleanly.
