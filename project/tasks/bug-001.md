# bug-001 Connect oxygen timer to active gameplay session

## Status

- status: todo

- commit message: `bug-001 connect oxygen timer to gameplay session`

## Goal

Make oxygen loss occur during active gameplay so the MVP loss condition can be tested and experienced.

## Severity

- severity: high
- reason: QA scope requires oxygen loss condition, but oxygen remains at 100% because the app never advances resource time.

## Reproduction Steps

1. Start the app.
2. Skip or complete the intro.
3. Wait during normal gameplay.
4. Observe the O2 HUD.

## Expected Behavior

- O2 should decrease over time according to the active session mode.
- Debug mode should drain from 100% to 0% over 15 minutes before power multipliers.
- When O2 reaches 0%, the terminal failure overlay should appear.

## Actual Behavior

- `advanceResourceTime` exists in `src/game/resourceState.ts`, but `src/App.tsx` never calls it.
- O2 remains at 100% unless resource state is manually changed by code.
- The oxygen loss condition cannot be reached through normal gameplay.

## Affected Files

- `src/App.tsx`
- `src/game/resourceState.ts`

## Suggested Fix

- Add an interval or animation-frame based session timer in `App`.
- Call `advanceResourceTime` while the intro, ending confirmation, and terminal failure states are handled intentionally.
- Keep debug mode active for MVP QA unless PM decides to expose normal/debug mode selection.

## QA Evidence

- `rg "advanceResourceTime" src/App.tsx src/game` shows the function is defined but not used by the app.
- `npm run build`: pass
- `git diff --check`: pass
