# bug-002 Enforce blackout interaction lock in gameplay UI

## Goal

Disable relevant gameplay interactions during blackout so the visual blackout state matches the deterministic resource rules.

## Severity

- severity: medium
- reason: Blackout visuals are shown, but player interactions are not guarded by the existing interaction lock helper.

## Reproduction Steps

1. Trigger repeated wrong submissions until power reaches 0%.
2. Observe the blackout alert and blackout visual wash.
3. Try selecting files, removing evidence tags, submitting evidence, unlocking security, or running Log_Fixer.exe.

## Expected Behavior

- During blackout, gameplay interactions should be disabled or clearly blocked.
- After blackout recovery, interactions should become available again.

## Actual Behavior

- `getInteractionLocked` exists in `src/game/resourceState.ts`, but `src/App.tsx` does not use it.
- `isBlackout` only controls visual classes and alert copy.
- Buttons/forms remain governed by unrelated disabled conditions such as locked directories or ending-ready state.

## Affected Files

- `src/App.tsx`
- `src/game/resourceState.ts`

## Suggested Fix

- Derive `interactionLocked` from `getInteractionLocked(resourceState)`.
- Disable evidence submit, file rows, password submit, recovery action, and tag removal while interaction is locked.
- Show a short ECHO/SYSTEM message or form hint explaining blackout recovery.

## QA Evidence

- `rg "getInteractionLocked" src/App.tsx src/game` shows the helper is defined but not used by the app.
- `npm run build`: pass
- `git diff --check`: pass

## Implementation Notes

- Connected `getInteractionLocked(resourceState)` to the active gameplay UI.
- Disabled file selection, evidence tag removal, evidence textarea, evidence submission, security unlock, and Log_Fixer recovery while blackout lock is active.
- Added handler-level guards so interaction state cannot mutate during blackout even if an event fires unexpectedly.
- Added visible blackout lock feedback near the ECHO evidence form.
